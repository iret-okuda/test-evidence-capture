# Test Evidence Capture

Webアプリ上のDOM要素を右クリックで選び、選択した全要素を含む最小の範囲をPNGで保存するChrome拡張です。スクリーンショット範囲を毎回ドラッグで微調整せず、現在表示中のviewportからテスト証跡を素早く取得できます。

## MVPの範囲

- Chromeツールバーの拡張機能アイコン、またはショートカットで撮影モードを開始
- 起動時にテスト番号とbefore/after/resultを指定する小型パネルを表示
- prefix、番号、番号ON/OFF、区分、区分ON/OFF、Tooltip設定を記憶し、次回起動時に復元
- 確認ダイアログ付きの「入力設定をクリア…」で入力項目だけを初期化
- №（2）・№（3）をチェックボックスで省略可能。№（2）をOFFにすると№（3）もOFF
- 未指定時はChrome既定のダウンロード先へ保存し、変更した保存先は画面更新・モード終了後も記憶
- DOM要素をホバーして枠を表示
- `pointer-events: none`が指定されたdisabledフォーム要素も、表示矩形から補完して選択
- 右クリックまたは`Space`で単一選択、`Shift + 右クリック`または`Shift + Space`で追加・解除
- 折りたたみ式の選択DOM一覧から、保存PNGへ赤枠を付けるDOMを指定
- 撮影モード中も左クリックはページへ通し、Webアプリを通常どおり操作可能
- 表示中の`[role="tooltip"]`、`.tooltip-content`、`.tooltip[data-tip]`の疑似要素を撮影範囲へ自動追加
- `ArrowUp`で親要素、`ArrowDown`で直前の子要素へ移動
- 選択した全要素の外接矩形に8 CSS pxの余白を付けてcrop
- 実際に保存される外接矩形を緑の破線と「スクショ範囲」ラベルで可視化
- Retina Displayを含む実画像倍率に合わせてPNG保存
- `AC-1-1-1-before.png`、`AC-1-1-1-result.png` 形式の証跡ファイル名で保存。区分は省略可能
- 1枚保存しても撮影モードを維持し、`Escape`でのみ終了
- 撮影モード中に同じURLを画面更新した場合、更新後に撮影モードを自動復元
- 直近5件のDOM選択をモード終了後も保持し、現在のスクロール位置で再計算して即時再撮影
- `Escape`で撮影UIと一時状態をすべて破棄

## ファイル構成

```text
.
├── manifest.json
├── background.js
├── bounds.js
├── annotations.js
├── filename.js
├── storage.js
├── history.js
├── content.js
├── icon.png
├── tests/
│   ├── bounds.test.js
│   ├── annotations.test.js
│   ├── filename.test.js
│   ├── storage.test.js
│   └── history.test.js
└── README.md
```

各ファイルの役割は次のとおりです。

- `manifest.json`: Manifest V3設定、権限、ツールバーアクション、変更可能なキーボードショートカットを定義します。
- `background.js`: アイコンのクリックまたはショートカットを現在のタブへ通知し、`captureVisibleTab()` とPNGダウンロードを実行します。
- `bounds.js`: DOM矩形の外接範囲、viewportへのclamp、実画像pixelへの変換を担当します。
- `annotations.js`: 赤枠の4px余白、viewport clamp、crop画像pixelへの座標変換を担当します。
- `filename.js`: テスト番号入力の正規化と証跡ファイル名の組み立てを担当します。
- `storage.js`: 選択したディレクトリへのPNG書き込み、同名ファイルの連番処理、ディレクトリハンドルの永続化を担当します。
- `history.js`: DOM選択・赤枠指定履歴のデータ検証と最大5件の制御を担当します。
- `content.js`: 撮影モード、入力パネル、DOM一覧、ホバー・選択・赤枠UI、親子移動、Canvas cropを担当します。
- `icon.png`: Chromeツールバーと拡張機能一覧に表示するアイコンです。
- `tests/bounds.test.js`: 外接矩形、余白、viewport clamp、Retina相当の倍率変換、Tooltip疑似要素の座標変換を検証します。
- `tests/annotations.test.js`: 赤枠の4px余白、画面端clamp、Retina相当のcrop座標変換を検証します。
- `tests/filename.test.js`: prefix、任意の№（2）・№（3）、before/after/resultと区分ON/OFFから期待するファイル名が作られることを検証します。
- `tests/storage.test.js`: PNGデータ変換、選択ディレクトリへの書き込み、同名ファイルの連番処理を検証します。
- `tests/history.test.js`: DOMロケーター履歴の検証、不正・旧形式データの除外、最大5件の保持を検証します。

## 設計

content scriptは選択要素の `getBoundingClientRect()` を集約し、8pxの余白を加えて `window.innerWidth` / `window.innerHeight` 内へclampします。この座標はviewport基準なので、ページのスクロール量を加算しません。fixed/sticky要素も、現在viewportに描画されている位置のまま扱います。

確定したCSS pixel座標は `{ bounds, viewport }` としてruntime messageでbackgroundへ渡します。backgroundは同じメッセージ処理内で `captureVisibleTab()` を行い、PNGとcrop情報をまとめてcontent scriptへ返します。Canvasを利用できるcontent scriptが実際のcropを担当し、完成したPNGだけをbackgroundへ送り直してダウンロードします。

確定時は撮影セッションを残したまま全オーバーレイを一時的に隠し、2回の描画フレームを待ってからbackgroundへ撮影を依頼します。画像取得後はUIを復元するため、選択要素・ファイル名入力・保存先を維持したまま連続撮影できます。`Escape`を押した場合だけ、オーバーレイ、イベントリスナー、一時状態をすべて削除します。

撮影モードのON状態はタブIDと現在のorigin・pathname・queryを組み合わせ、`chrome.storage.session`へ保持します。同じURLを再読み込みすると、新しいcontent scriptが状態を照会して撮影モードを自動的に開始します。`Escape`で終了した場合、別URLへ移動した場合、タブを閉じた場合は記録を削除します。選択DOMは復元しませんが、永続化済みの証跡入力設定・保存先・履歴は引き継ぎます。

証跡入力設定は `chrome.storage.local` へ保存します。prefix、3つの番号、№（2）・№（3）のON/OFF、before/after/result、区分ON/OFF、Tooltip設定が対象で、撮影モード終了後や画面更新後も復元します。「入力設定をクリア…」は確認ダイアログで了承した場合だけこれらを初期値へ戻します。保存先とスクショ履歴はクリア対象に含めません。

選択要素、表示中Tooltip、8px余白から計算した最終外接矩形は、緑の破線と「スクショ範囲」ラベルで常時表示します。この枠も撮影時に他の拡張UIと一緒に隠すため、PNGには映りません。

「選択中のDOM」は初期状態で閉じた折りたたみ欄です。展開すると高さ144pxの縦スクロール一覧を表示し、選択DOMを `tag#id.class — text` 形式で確認できます。チェックしたDOMには、境界から4 CSS px離した位置へ3 CSS pxの赤枠をプレビューします。未チェックDOMも従来どおり撮影範囲へ含まれます。

backgroundが返すPNGの実寸を基準に、次の倍率を個別に求めます。

```js
const scaleX = image.width / viewportWidth;
const scaleY = image.height / viewportHeight;
```

CSS座標へこの倍率を適用してCanvasでcropします。`devicePixelRatio` の値を直接仮定しないため、Chromeが返した画像に対してRetina Displayのpixel差を正しく反映できます。撮影時はプレビューを含む拡張UIをすべて隠し、crop後のCanvasへチェック済みDOMの赤枠だけを描画します。

保存先を変更しない場合は `chrome.downloads` を使い、Chromeで設定されている既定のダウンロード先へ保存します。「変更…」を押した場合は、ユーザー操作を起点にFile System Access APIのディレクトリ選択ダイアログを開きます。初回はDownloadsを開始位置として提案し、選択したディレクトリハンドルをIndexedDBへ保存するため、撮影モード終了後や同じページoriginの画面更新後も復元できます。ブラウザが再許可を必要とする場合は「再許可…」と表示し、クリックでアクセス権を復元します。同名ファイルがある場合は ` (1)`、` (2)` のように連番を付け、既存ファイルを上書きしません。

撮影成功時には選択DOMのロケーター、赤枠対象のロケーター配列位置、撮影時の範囲、ページのoriginとpathname、ファイル名を `chrome.storage.local` へ保存します。ロケーターは一意な `data-testid` / `data-test` / `data-cy` / `data-test-id`、一意な `id`、`nth-of-type` を含むDOMパスの順で作成します。履歴は全体で直近5件まで保持し、現在と同じページのものだけをパネルへ表示します。赤枠情報を持たない旧形式のDOM履歴は、赤枠なしとして引き続き利用できます。

履歴ボタンを押すと保存したロケーターからDOMを再取得し、その時点の `getBoundingClientRect()` で範囲を再計算します。そのため、撮影後にページをスクロールしても、対象DOMを現在のviewport内へ表示しておけば同じ要素を撮影できます。対象DOMが削除された場合やviewport外にある場合は、古い画面座標を代用せず撮影を中止してパネル下部へ理由を表示します。

オーバーレイはページCSSから隔離したclosed Shadow DOM内の固定要素です。枠は `pointer-events: none`、入力パネルだけは操作可能にし、拡張専用ホストを判定してDOM選択対象から除外します。DOM選択に使う右クリック系イベントはcapture phaseで `preventDefault()`、`stopPropagation()`、`stopImmediatePropagation()` を行い、ページ側の右クリック処理とコンテキストメニューを抑止します。左クリック系イベントは抑止せず、撮影モード中もリンク、ボタン、フォームなどを通常どおり操作できます。

## Chromeへのインストール

1. Chromeで `chrome://extensions` を開きます。
2. 右上の「デベロッパー モード」を有効にします。
3. 「パッケージ化されていない拡張機能を読み込む」を選びます。
4. このディレクトリを選択します。
5. Chrome上部のパズル形の「拡張機能」メニューを開き、`Test Evidence Capture` のピンを有効にします。
6. 必要に応じて `chrome://extensions/shortcuts` を開き、`Test Evidence Capture` のショートカットを変更します。

初期ショートカットはmacOSが `Command + Shift + S`、その他が `Ctrl + Shift + S` です。ChromeやOSの既存ショートカットと競合する場合は手順6で変更してください。

ローカルHTMLで利用する場合は、拡張機能の詳細画面で「ファイルのURLへのアクセスを許可する」を有効にしてください。

## 操作方法

1. 証跡を取得するタブで、Chrome上部にピン留めした `Test Evidence Capture` のアイコンをクリックします。ショートカットでも開始できます。
2. 右上のパネルでprefixと番号を指定し、`before`、`after`、`result`から区分を選択します。初期値は `AC`、`1`、`1`、`1`、`before` で、3つの番号と区分はすべて有効です。番号欄はスピンボタンで1ずつ増減できます。
3. №（2）または№（3）が不要なら、見出し横のチェックをOFFにします。№（2）をOFFにすると№（3）も自動的にOFFになり、№（2）を再びONにするまで№（3）は選択できません。
4. 保存先を変える場合は「変更…」を押し、OSのダイアログからディレクトリを選択します。変更しなければChrome既定のダウンロード先へ保存されます。保存先は次回起動時に復元され、権限の再確認が必要な場合だけ「再許可…」を押します。
5. 対象DOMへマウスを移動します。オレンジの枠がホバー対象です。
6. 右クリックまたは`Space`でその要素だけを選択します。青い枠が選択対象です。右クリック時はブラウザのコンテキストメニューを表示しません。
7. 必要に応じて `Shift + 右クリック`または`Shift + Space`で要素を追加します。選択済み要素へ同じ操作をすると解除します。左クリックはWebアプリ本来の操作に使えます。
8. 赤枠を付ける場合は「選択中のDOM（件数）」を展開し、対象行へチェックを入れます。チェックしたDOMだけ、少し余白を空けた赤枠で囲まれます。
9. 細かい子要素をホバーした場合は `ArrowUp` で親へ移動します。`ArrowDown` で直前にたどった子へ戻れます。
10. `Enter` を押すと、全選択要素を含む1枚のPNGを保存します。保存後も撮影モードは続くため、入力や選択を変更して次の証跡を撮影できます。
11. 同じDOMを再撮影する場合は、対象が現在のviewport内に見える位置までスクロールして「直近のDOM選択」の履歴ボタンを押します。確認操作なしで、赤枠指定も含めて現在の位置から再計算し、現在の番号・区分・保存先を使って即時撮影します。

撮影モードを終了する場合は `Escape` を押します。保存名は有効な番号だけを使います。初期値では `AC-1-1-1-before.png`、№（3）がOFFなら `AC-1-1-before.png`、№（2）がOFFなら `AC-1-before.png` です。`result`なら末尾は`-result.png`になり、「区分を付ける」をOFFにすると`AC-1-1-1.png`のように区分なしで保存します。

撮影モード中にページを更新した場合は、読み込み完了後に撮影モードが自動的に再開します。証跡入力設定は保存値から復元されますが、更新前に選択していたDOMはリセットされるため、必要な要素は再選択してください。`Escape`を押してから更新した場合は自動再開しません。

証跡入力設定を初期値へ戻す場合は、パネル上部の「入力設定をクリア…」を押し、確認ダイアログで了承します。キャンセルした場合は何も変更しません。クリアしても選択済みの保存先と直近のDOM選択履歴は残ります。

### Tooltipを撮影する

パネルの「表示中のTooltipを含める」は初期ONです。Tooltipを開く要素へカーソルを置き、Tooltipが表示された状態で`Space`、続けて`Enter`を押します。選択した起点要素は青枠、撮影範囲へ自動追加されたTooltipは紫の破線枠で表示されます。下部にも「Spaceで選択済み・Tooltipも撮影対象」と表示し、両方の外接矩形を1枚に保存します。

通常の`role="tooltip"`を持つDOM要素に加え、daisyUI形式の`.tooltip[data-tip]::before`本文と`::after`矢印にも対応しています。疑似要素はDOMの `getBoundingClientRect()` へ含まれないため、実際のcomputed styleから幅、高さ、inset、transformを取得してviewport座標へ変換します。

## 既知の制限

- 現在のviewport内だけを撮影します。ページ全体をスクロールしながら結合しません。
- iframe内部、Shadow DOM内部の要素選択には対応していません。iframe自体は1要素として選べます。
- `pointer-events: none`要素の補完選択は、`:disabled`または`aria-disabled="true"`の要素が対象です。一般的な非活性要素ではない任意の`pointer-events: none`要素までは補完しません。
- viewport外の部分、横スクロール領域の非表示部分は画像に含まれません。
- sticky要素の重複除去、動画、OCR、文字・矢印・自由描画の注釈はありません。注釈は選択DOMの赤枠だけです。
- transformで回転したDOMも、`getBoundingClientRect()`が返す軸平行の外接矩形を赤枠で囲みます。
- Tooltip自動検出は通常DOM内の`role="tooltip"`、`.tooltip-content`、`.tooltip[data-tip]`が対象です。それ以外の独自クラスやShadow DOM内のTooltipは自動検出できません。
- Chrome内部ページ（`chrome://`）、Chrome Web Storeなどcontent scriptを実行できないページでは利用できません。
- 画面更新後の自動復元は同じタブ・同じorigin・pathname・queryの場合だけです。別URLへの遷移やブラウザ再起動後は自動ONになりません。
- File System Access APIを利用できないページや環境では、「変更…」後の表示が「保存時に選択」へ変わり、`Enter`後に「名前を付けて保存」ダイアログを表示します。
- 保存先はページoriginごとにIndexedDBへ記憶します。別originのWebアプリ、サイトデータ削除後、シークレット環境では再選択が必要です。Chromeの権限状態によっては画面更新後に「再許可…」のクリックが必要です。
- DOM履歴のロケーターはページの属性とDOM構造に依存します。対象DOMの削除、`id`やテスト属性の変更、DOM階層の変更によって解決できなくなった履歴は撮影できません。
- 履歴の対象DOMは撮影時点で現在のviewport内に一部でも表示されている必要があります。履歴から自動スクロールは行いません。
- 座標を保存していた旧形式の履歴はDOMを特定できないため表示されません。新しく1枚撮影すると、有効なDOM形式の履歴だけで保存し直されます。
- 履歴はoriginとpathnameが同じページだけ表示します。query parameterとhashの違いは同じページとして扱います。
- ブラウザズーム100%をMVPの基本条件としています。倍率は実画像から算出するため他のズーム率でも原理上追従しますが、手動確認の対象です。
- ページが撮影確定直後に大きくレイアウト変化した場合、確定時のDOM範囲と撮影フレームが一致しない可能性があります。
- 撮影や保存に失敗した場合、詳細は対象タブまたは拡張のService WorkerのDevToolsコンソールへ出力されます。

## 手動確認項目

- ツールバーアイコンのクリックで撮影モード表示が出ること
- 起動時に右上へファイル名入力パネルが表示されること
- prefix、各番号、№（2）・№（3）のON/OFF、区分、区分ON/OFF、Tooltip設定を変更し、`Escape`後の再起動でも値が復元されること
- 上記入力を変更して画面更新した場合も、更新後に値が復元されること
- 「入力設定をクリア」を押すと確認が表示され、キャンセル時は入力値が変わらないこと
- クリアを了承すると`AC`、番号`1-1-1`、全番号ON、`before`、区分ON、Tooltip ONへ戻ること
- 入力設定をクリアしても、選択した保存先と直近のDOM選択履歴が残ること
- 3つの番号欄をスピンボタンで1ずつ増減できること
- №（3）だけをOFFにすると、№（1）-№（2）だけのファイル名になること
- №（2）をOFFにすると№（3）もOFF・無効になり、№（1）だけのファイル名になること
- №（2）を再びONにした後、№（3）を個別にONにできること
- `before` / `after` / `result` の押下状態がグレーで切り替わること
- 「区分を付ける」をOFFにすると3つの区分ボタンが無効になり、ファイル名から区分が省略されること
- 「区分を付ける」を再びONにすると、OFF前に選択していた区分が復元されること
- パネルをクリックしてもDOM要素として選択されないこと
- prefixまたは番号入力欄にフォーカスが残った状態でも、`Enter`で保存できること
- 保存先の初期表示が「ダウンロード（既定）」で、変更しなければChrome既定のダウンロード先へ保存されること
- 「変更…」でOSのディレクトリ選択ダイアログがDownloadsから開き、選択したフォルダ名がパネルへ表示されること
- 選択したディレクトリへPNGが保存され、同名ファイルがある場合は連番が付いて上書きされないこと
- ディレクトリ選択をキャンセルした場合、元の保存先設定が維持されること
- `Escape`後の再起動や同じoriginの画面更新後も選択した保存先が復元されること
- 権限の再確認が必要な場合は「再許可…」が表示され、クリック後に保存先が復元されること
- ショートカットを設定している場合、ショートカットでも撮影モード表示が出ること
- ホバー枠が対象DOMへ追従し、ページのレイアウトが動かないこと
- `disabled`かつ`pointer-events: none`のbuttonへカーソルを置くと、親ではなくbutton自身をホバー・選択できること
- `aria-disabled="true"`かつ`pointer-events: none`の要素も表示矩形から選択できること
- 右クリックで既存選択が解除され、1要素だけ選択され、コンテキストメニューが出ないこと

- DOMの追加・解除・ページ側での削除に、一覧・件数・赤枠状態が追従すること

- `Space`選択時、起点要素が青枠になり、下部へSpaceで選択したことが表示されること
